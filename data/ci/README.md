# data/ci/ — CI Quality Gate Reference Data

This directory contains **git-committed** reference data used exclusively by the
GitHub Actions CI/CD quality gate workflow (`.github/workflows/model-quality-gate.yml`).

## Why this directory exists

The model quality gate needs a fixed, reproducible test dataset to evaluate the ML
pipeline on every PR that touches training code. This data must be:

- **Available without DagsHub** — GitHub runners have no network path to DagsHub
- **Immune to DagsHub wipe** — the "Wipe DagsHub" button must not destroy CI
- **Small enough for git** — synthetic signals, not production data
- **Stable** — only changes when the training pipeline fundamentally changes

## Files

| File | Purpose |
|------|---------|
| `quality_gate_signals.csv` | Golden reference signals for the quality gate (raw amplitudes + labels) |

## Signal generation

Signals are generated by `scripts/generate_ci_quality_gate_data.py` using the
**exact same defaults** as the Streamlit UI Greenfield use case (`BootstrapConfig` defaults):

- **Healthy (Gaussian):** μ∈[48,52], σ∈[2.0,3.0], H∈[2.5,3.0], noise∈[0.01,0.02]
- **Unhealthy (Lorentzian):** μ∈[42,58], γ=σ×1.1775, σ∈[3.8,5.1], H∈[1.0,1.5], noise∈[0.06,0.10]
- Fixed seed: 42, n_samples: 160 (80 healthy + 80 unhealthy)

## CSV format

`quality_gate_signals.csv` columns:
- `label` — 0 = healthy (Gaussian), 1 = unhealthy (Lorentzian)
- `shape_type` — `gaussian` or `lorentzian`
- `a_0` through `a_100` — signal amplitude values (101 uniform time points: 0..100)

Time is reconstructed as `np.linspace(0, 100, 101)` — not stored (uniform spacing).

## When to regenerate

Only regenerate when:
1. The feature extraction pipeline changes (new features added/removed/renamed)
2. The signal generation parameters change (BootstrapConfig defaults changed)
3. The number of features changes

**When regenerating:** run `python scripts/generate_ci_quality_gate_data.py`, then
commit the updated CSV and update the quality gate thresholds in `params.yaml` if needed.

## DO NOT

- Add a `.dvc` file for these CSVs — DagsHub wipe would destroy them
- Exclude these files with `.gitignore` — they must be version-controlled in git
- Generate them at CI runtime — they must be committed as fixed references
